# 记忆需要为尚未出现的问题保留什么？

一份记忆在写入当天足够有用，几个月后却可能无法回答一个很自然的问题。期间记录没有损坏，系统也未必忘掉更多东西。发生变化的可能只是人后来想拿它做什么。

设原事件说：Mira 曾因客户约束为 v1 选择 CSV，后来 v2 改用 JSON。一个当时合理的概括是“当前版本使用 JSON”。用它回答今天该传什么格式很直接；后来有人想知道旧项目为什么选 CSV，概括中已经没有相应区别。再后来，要核对究竟是谁说过那句话，需求又变了一次。

AMS 现有的[表示与取用协议](../../research/representation-use-study/protocol.md)已经区分原事件、概括和并存，也要求逐问题判断可用信息。这篇研究继续往前一步：**什么条件使“信息足够”成为可检查的判断？当未来用途还未出现时，提前固定一种表示，究竟固定了什么？**

本轮完成一项有限推导和一组原创枚举。它没有提出新的充分性定理，也没有运行自然语言模型。研究所得是一种更明确的观察单位，以及几种能推翻过强主张的反例。

## 先写出系统实际看见的东西

令 `H` 表示我们声明的一组可能历史，`T(h)` 表示给定写入过程留下的可见表示，`q` 表示后来出现的问题。原文、摘要、结构化关系与检索包都可能成为 `T` 的具体对象，选择哪一个要在研究开始时说明。

知识背景与可用通道也属于前提。例如，“v2 是当前版本”若是所有情境共有的背景，应明说；如果只有实验作者知道某个标识对应哪件事，就不能让该标识代替内容。当前上下文提供了额外证据时，观察应写成 `(T(h), context)`。模型先验、外部工具与未声明的语料可能进一步改变可辨认的范围，这份有限模型不把它们悄悄算进去。

对于某个可见值 `z`，所有会产生它的历史组成一个观察类：

```text
C_T(z) = { h ∈ H : T(h) = z }
```

这里真正需要问的是：在同样的输入面前，这些可能历史是否允许同一个回答？只检查一条摘要中有没有某个字段，无法回答这一问题；字段可能以别的形式保存，字段名也可能存在却失去原来的绑定。

## 允许多个答案时，要检查整个类

为每个历史和问题声明一个可接受答案集 `A(h,q)`。它可以只有一个元素，也可以包含几种都合法的表达或行动。我们要求 decoder 对 `(z,q)` 输出一个答案；在全部仍可能的历史里都满足合同的条件是：

```text
⋂ { A(h,q) : h ∈ C_T(z) } ≠ ∅
```

证明很短。若共同交集为空，任何选择都会至少被该类中的一个历史排除，因此仅凭这个观察无法对整个类保证满足合同。若每个观察类、每个问题的交集非空，就可以在各交集中选一个元素，得到这个有限任务合同上的一个抽象回答函数。

第二个方向只是存在性。有限集合上的表可以被写出来，并不说明我们已经获得可泛化的语义解码器；更没有证明某个 LLM 能找到那张表。为了避免把“条件允许”写成“系统做到了”，本文把该结果称为**有限兼容性**。后续的模型消费仍是独立研究。

两两检查还不够。设三个历史分别接受 `{A,B}`、`{B,C}`、`{A,C}`。任意两个历史都有共同答案，但三个历史无法共同接受任何一个答案。本文的可执行控制实际计算了这三个集合，并找到一个大小为三的最小冲突见证。如果只记录成对的“没有矛盾”，就会错过这个障碍。

暂缓也需要进入合同。若所有历史、所有问题都允许“我不知道”，兼容性立即变得空洞。本次的完整记录任务要求具体回答，未将暂缓设为万能正确选项。真实应用里，有证据不足、授权不足或语义歧义的情境，应该单独声明允许暂缓的条件，并区分恰当暂缓与本可回答却停下。

## 新的问题怎样把旧的历史重新分开

先考虑答案唯一的特例。对于任务族 `Q`，定义两段历史在所有这些任务上都要求相同答案时属于同一类：

```text
h₁ ~Q h₂  ⇔  对每个 q ∈ Q，都有 a(h₁,q) = a(h₂,q)
```

若表示把任务仍需要区分的两段历史合并，就存在至少一个问题无法被共同满足。反过来，一个表示可以丢掉大量对 `Q` 无关的区别，同时保留所有这些任务需要的答案。这里并不需要完整重建原历史。

现在让 `Q_now` 扩展为 `Q_future`。新问题可能把原先等价的历史拆开；它不会把已有任务要求不同答案的历史重新合并。存储内容无需变化，“足够”的判断已经可能变化。对多答案合同，同样可以用全类交集表达这个单调关系，但“两两拥有共同答案”通常不构成等价关系，不能直接拿来分区。

这给“记忆应该保留什么”增加了时间维度：写入时所针对的任务族，和后来需要回答的任务族，可能不同。未来用途尚未知道，并不意味着一定要完整保存一切；它意味着压缩的取舍需要同时说明预期用途、允许的损失，以及什么时候能重新取得原文。

## 与已有充分性和压缩问题的关系

这是一项有限任务合同下的辨析，并无理论首创主张。Tishby、Pereira 与 Bialek 的[原始 Information Bottleneck 论文](https://arxiv.org/pdf/physics/0004057)在给定联合分布 `p(x,y)` 时，用 `I(X;Z) − βI(Z;Y)` 表达压缩输入与保留相关目标信息的目标（§3，Eq.14–15）。这里的目标 `Y` 参与了问题定义；它不直接保证一个尚未声明的新任务仍然可回答。

本文暂不估计概率、互信息或期望损失，因此不能把有限观察类数叫作信息瓶颈分数。下一步若引入任务分布，必须说明该分布来自哪里、变化后怎样评价，以及极少发生但不能答错的任务是否需要另一种保证。全任务的稳健合同与平均风险会回答不同的问题。

[LLMLingua-2](https://arxiv.org/html/2403.12968v2)的 Introduction 与 Related Work 明确讨论 task-aware 与 task-agnostic 压缩；未来查询是否已知应成为比较的条件。把查询已知的方法和写入时未知查询的方法放在同一张表里，可以比较整套策略，但不能把所有差异归到压缩器本身。

## 32 个历史给出的正例与反例

[完整方法、输入和 runner](../../research/task-relative-sufficiency/README.md)枚举了 32 个原创历史：v1 格式、v2 格式、v1 说话人、v1 明确理由各有两个值，逐字措辞另有两个版本。所有数据来自公开可检查的生成规则。它们是可能世界，不能当作 32 位参与者或独立经验样本。

所有投影都在收到问题之前形成，只读取事件本身。审计 ID、可接受答案集与检查结果不会传入投影。材料、投影和问题均由本轮共同设计，是用于检验机制的开发构造；未来任务没有对设计者保密，不能称为 held-out 泛化实验。任务随后依次扩大：先问当前格式，再问旧格式、说话人和明确理由，最后要求旧记录的逐字措辞。

| 可见表示 | 观察类数 | 当前格式 | 四项语义任务合计 | 再加入逐字措辞 |
| --- | ---: | --- | --- | --- |
| 当前概括 | 2 | 全类兼容 | 存在空交集 | 存在空交集 |
| 版本与格式关系 | 4 | 全类兼容 | 存在空交集 | 存在空交集 |
| 版本、格式、说话人、明确理由 | 16 | 全类兼容 | 全类兼容 | 存在空交集 |
| 从当前概括继续扩写 | 2 | 全类兼容 | 存在空交集 | 存在空交集 |
| 原始合成事件 | 32 | 全类兼容 | 全类兼容 | 全类兼容 |

中间的 16 类是一个必要正对照。它把措辞不同的历史合并了，仍然保留全部已声明语义任务的可接受答案。由此不能得出“概括必然破坏记忆”。逐字任务后来出现时，这个相同表示才显露出边界。

当前概括也没有被判为一无是处。它准确保留了当前任务需要的区别。研究追踪的是用途扩展后哪些历史变得必须区分，不能把新问题上的障碍倒写成当初所有使用都失败。

所有观察类、共同答案和最小冲突见证都保存在[结果文件](../../research/task-relative-sufficiency/results.json)。这些数字没有估计真实记忆系统的发生率，也不构成模型排名或 token 预算比较。

## 扩写和重新取得证据，改变的是不同对象

设后续过程只接收旧表示，再做确定性变换 `g`。原先 `T(h₁)=T(h₂)` 的历史仍满足 `g(T(h₁))=g(T(h₂))`。这个过程可以合并更多观察类，无法把已经合并的一类拆开。原类对应的全局答案交集若为空，合并更多历史也不能让它重新非空。

因此，一段更长、更整齐的说明并没有凭空恢复已经丢掉的区别。这里的“无法”受前提约束：过程只能读取 `T`；若它查询原文、利用新的上下文或得到其他外部信息，观察已经改变，不能继续用只读 `T` 的论证解释它。

增加关系也值得这样区分。若原事件保持可访问，同时增加可撤销的派生关系，新的联合观察至少保留原先的区别。实际任务是否更好仍受有限预算、检索、冲突和消费机制影响。把多种表示一起堆进 context，有可能增加干扰；这一性能问题不会推翻信息层面的包含关系。

原文重访可以让某次任务获得更细的观察。它需要检查实际过程：访问是否获准，源是否仍在，版本是否对应，目标是否绑定正确，取回范围是否足够。本模型把审计标识排除在观察外，也未给 locator 声明可解码语义或查表映射，因此不能把它自动算作原文已经到场。若另一种系统的标识本身编码内容，或明确提供映射，必须将那份额外信息写入观察合同再分析。

本次合成 resolver 在五项条件全部通过时提供完整事件；逐项关闭后只留下当前概括及访问状态。前者让给定任务族全类兼容，后者保留后来的歧义。这是保守的全有或全无构造，未执行真实检索，也没有研究部分内容的收益。它只把一个常被跳过的前提显式化：**可重新取得的原文，要在实际取得以后才能算入这一轮观察。**

## 这条线与当前研究已经相遇在哪里

未知未来问题与写入承诺时机已是公开研究对象，不能把它们当作 AMS 首次提出的概念。下面比较的是各自做选择的时间与可见材料，跨论文分数没有可直接合并的共同实验。

| 工作与实际阅读范围 | 与本题相关的机制 | 本文由此继续追问什么 |
| --- | --- | --- |
| [LazyMem，v2](https://arxiv.org/html/2607.22690v2)，§3、§4.5 与 Appendix F | 在查询已知后，对较宽检索池做编辑和压缩；归因区分 retrieval miss、editing loss 与 QA reasoning | 编辑前的候选池能否区分目标历史？查询已知以后保住了哪些任务区别？ |
| [Test-Time Memory Construction，v1](https://arxiv.org/html/2610.13348v1)，Introduction 与 §3 | 离线保留轻量 episode metadata 和原文连接，在推理时迭代检索 metadata 与原记录；ReadRaw 依赖此前已见的 metadata | 链接可用和能发现它分别靠什么？原文重访具体提供了什么新观察？ |
| [Librarian Agents](https://arxiv.org/html/2610.22273)，§2 与 Appendix A.6 | 学习预先组织的层次文件系统，使用合成内容及引用，并保留原始来源恢复路径；构建器不见评测查询 | 预期用途怎样影响组织？论文的静态 QA 语料评价尚未回答持续新事件与后来新用途共同发生时的行为。 |
| [MemRefine，v1](https://arxiv.org/html/2606.13177v1)，§3.1 与方法说明 | 在未知查询和存储预算下提出优化目标，实际方法使用成对 LLM 判断的替代反馈 | 形式上的未知查询目标与实际判断器偏好之间，哪些区别仍未被检验？ |

这些来源分别提供 eager、query-conditioned、anticipatory 及迭代构造的具体实例。本文没有复现它们，也没有验证它们的效果主张。AMS 的推进位置更窄而明确：为某次比较写出观察和任务合同，构造能使该表示失败的历史类，再追踪新增信息究竟从哪里进入。

还需要把索引表示和最后送给模型的值分开。[LongMemEval 的 arXiv v2 稿](https://arxiv.org/html/2410.10813v2)的 §4.2、§5.2–5.3 区分 key 与 value：概括或事实替换原值，与用事实扩展检索 key 后仍提供原值，保留的信息不同。作者报告的聚合结果与多 session 子任务也不完全同向。这是对任务条件的提醒，不能推出所有概括都坏或原文总优；本文未重跑该研究。

已有[候选竞争研究](../../research/experience-reuse-retrieval-study/README.md)说明原文仍在存储里也可能进入不了有限候选；本研究说明候选中已到场的表示仍可能不足以区分历史。两者可以串联，却不能互相代替。[FluctlightDB 的 observation-binding 审计](../../research/fluctlightdb-observation-binding-audit/README.md)进一步提醒：若查询与目标历史的绑定不足，一个 exact-ID 分数无法独自解释排序机制。此前的这些证据促成当前问题，没有共同证明某种架构优越。

## 下一阶段怎样产生更有分辨力的结果

接下来可以沿这条线形成一个持续研究单元，先区分两种变化。**用途变化**固定事件资料，只改变问题；**世界变化**加入新事件或有范围的更正。两者同时改变时很容易把无法回答历史问题误读成没有学会更新。

| 资料状态 | 原任务族 | 扩展任务族 |
| --- | --- | --- |
| 固定原事件 | 观察既定表示的基线 | 单独研究后来用途所需的新区别 |
| 加入新事件或更正 | 观察更新怎样影响应改变与应保留部分 | 研究用途变化与状态更新的交互 |

自然语言的下一项研究应先固定原创事件组、任务族、可接受答案及 source coverage，然后比较相同材料下的提交时机：写入时概括、回答时重构、带来源的预先组织。模型、输入实际预算、可用工具及可重访源范围需要各自明示。完整信息条件与等预算条件分别报告；事后按某模型的成功重新定义答案集会污染比较。

原协议中的原事件／概括／并存三臂仍有价值。离线 scripted/oracle controls 已有保存结果；完整自然语言与 provider 效果比较仍未执行。这次推导可以为它补上两类材料：存在清楚冲突见证的输入，以及可压缩但仍充分的正对照。随后分别报告表示中缺失的信息、源文未送达、已送达后未使用，以及实际答案的可接受性。当前的枚举没有替任何一个环节生成模型效果。

另一条独立理论线可以进一步讨论任务分布与预算。要求所有未来问题都能回答通常过强；给定问题分布和损失函数之后，可以比较平均风险，或者针对某些关键用途提供更强保证。Information Bottleneck 提供了一个已核对的起点。统计充分性、实验比较和率失真仍可作为后续阅读方向，本轮不宣称已经完成这些理论的全文对读。本文先保留有限、无概率的合同，随后再决定哪一种理论真正改变解释。

## Relata 与 AMS 在这里怎样继续

[Relata](https://github.com/IndelibleVivi/Relata)的现行定位是开放、以社区为基础的前沿记忆研究实验室。它把自身的 benchmark 研究、系统与源码研究集合、未来记忆系统的孵化放在一起；一般 agent memory 与成人长期人机情境都可以独立成为研究对象。定义辨析、架构研究、比较与批评各有研究价值，现有草稿和案例并未构成已经接受的 benchmark 或产品架构。

本次合作选择了其中一条线：[Relata 的未来问题与记忆研究草稿](https://github.com/IndelibleVivi/Relata/blob/research/future-question-memory-20261022/research/future-question-memory/README.md)用混合领域的叙事材料与输入合同检查后来用途需要哪些区别。核对原话、重新理解某件事、延续作品、辨别一次更正或在迁移后接回共同经历，都可以成为这一单元的具体问题；案例选择和人在场的判断仍需保留独立地位。链接指向本轮研究分支，表示可审阅的草稿，未把它提升为整个实验室的唯一路线。

AMS 在这里承担表示、任务与可用观察之间的形式化和基础解释；Relata 的这项单元承担情境、输入合同及其对后续系统比较提出的要求。两边可以交换问题和带边界的材料，仍保留各自更宽的研究范围。记忆使一个回答在信息上可能，并不自动授权提及它，也不保证表达方式合适。

本轮留下的变化是：讨论一份记忆时，除了问它保留了多少信息，还可以展示**哪些仍可能的历史被放在一起，它们面对哪一项后来任务无法共同满足，以及何种新增观察能够重新区分它们**。未来真实材料若显示所声明的历史集合、任务合同或源访问前提不成立，就需要改写相应判断。
