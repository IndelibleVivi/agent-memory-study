## 先认清三个角色

Jev 是接收状态与问题的 hosted decision model；Jev-Mem 是使用它的 memory architecture；System Two 是最后组织答案或生成抽象的模型。官方 Jev 文档说明同一权重服务各账户，不提供客户 fine-tuning / LoRA。把更多经历放进 state，改变了这一次判断的输入，还不能叫模型学会了你的经历。 同一批问题共享 state，但彼此独立；需要前一步答案才能决定的问题，要由调用方分阶段组织。

## 写入：先留下经历，之后再决定用途

论文保留合法 observation，给它记忆类型、时间和来源。当前随附 profile 关闭 admission；可选的拒绝入口存在，却不是这个配置的默认行为。这样做保留了“现在看不出价值，未来才需要”的可能，同时也把筛选负担交给后续关联与检索。类型分数低不自动意味着条目该消失。

## 关联：控制器只判断它见到的候选

向量、实体、关键词和时间先圈出附近记录，Jev 再判断语义与因果等关系，代码按阈值建边。候选生成漏掉某段关键经历，后面的判断再精确也无从补救。AMS 既有候选竞争实验提醒我们：保存、进入候选、排进 context 是不同节点；它没有测 Jev 的 embedding 或关系质量。

## 检索：停下来，不总是因为已经知道

Jev-Mem 按 query 分配图预算，从 anchors 开始，反复检查已有证据并扩展。充分回答、继续探索无益和预算耗尽都可能结束循环。把所有停止都算成“证据完整”，会掩盖缺证据但无路可找的状态。模型失败还会改变 routing、traversal 或 stopping 的处理，必须保留实际走过的路径。

## 维护：过时的判断，先落在哪里

当前 consolidation 询问重复、矛盾、obsolete 和表示选择；它记录判断、添加关系，在另有 summarizer 且门槛满足时增加派生节点。下面的源码实验给定判断值，观察执行路径怎样改变节点和索引。它刻意把“能否判断对”留给另一个实验，先回答“这个判断究竟能让代码做什么”。

## 遗忘：要退出的是哪个范围

设六月记录是“出差选靠窗”，九月说“这次受伤，选过道”。这是编者例子，未做模型测试。我们可能需要当前订票采用过道、保留六月的历史解释、让临时条件结束后原偏好仍有效。当前 context 不出现、以后不再检索、持久化副本清除、已训练参数影响撤回，各自需要机制；一个 obsolete 标量不能替它们完成工作。

## AMS 因而可以多问一层

AgeMem 关心学到的管理策略，已有学习专题关心经验如何改变后续选择，Jev 则提供固定模型上的可组合控制接口。把它们连起来后，下一问会更具体：判断准确了吗，执行改变了吗，后续任务受益了吗？三种证据分别成立，再讨论能迁移什么。
