# 找到一样的，还是找到相关的？

一个检索系统可以忠实返回最相似的对象，却没有满足当前需求。要理解这个差距，可以先把几个常一起出现的名字放回各自的操作中。

## 从 jieba、BM25、BGE-M3 开始

[jieba](https://github.com/fxsjy/jieba)提供中文分词等能力，影响文本以什么单位进入后续处理。[BM25](https://nlp.stanford.edu/IR-book/html/htmledition/okapi-bm25-a-non-binary-model-1.html)根据查询词项、文档词频与长度等因素计算匹配分数；词频的增益不是无限线性增长。[BGE-M3](https://bge-model.com/bge/bge_m3.html)支持 dense、sparse 与 multi-vector 三种检索表示，已经提醒我们：“神经”与“词项”并不是一条只能二选一的分界。

先有可比较的表示与打分目标，再选择访问和排序方法。这些角色可以由同一个软件组合实现；上面的区分不规定一条唯一流水线。

原创设定中，查询“如何撤回旧授权”可能需要找到只写“取消先前权限”的内容；另一个查询“错误码 E17”却需要保住精确符号。前者让我们关心泛化，后者让我们关心约束。哪一种表示适合，取决于需求和材料。这个例子不报告任何模型的实测表现。

### 把“神经”与“词项”放到两个不同的问题里

jieba 的 README 区分普通精确模式与会进一步切分长词的搜索模式。切成什么单位，会改变后面能出现哪些匹配；这与相关性评价中的 precision 不是同一个“精确”。

BGE-M3 的官方说明又给出一个有用的交叉：dense 路径用一个整体向量打分，sparse 路径给 token 学习权重，再累计查询与文档共有 token 的权重乘积；multi-vector 路径保留多个表示，先做细粒度匹配再汇合。于是，“是否依赖共有单位”与“权重怎样获得”可以分别回答。权重由神经网络产生，匹配仍可能建立在交集上。这里使用官方定义，不推断哪一路在现实任务中必胜。

仿照其中的加权交集形式，可以写下一个足够小的原创演算。为便于解释，我们手工把“撤回”和“授权”当作两个词项，**不模拟 BGE-M3 的实际 tokenizer 或输出**：

```text
查询权重：撤回 → 2，授权 → 1
L_raw(d) = 查询与文档共有词项的权重乘积之和
```

下面的 d₁、d₂、d₃ 与后面的 a–h 集合例子彼此独立。文本、词权重、dense 分数和相关性全部是教学设定；当前需求是找到撤回既有授权的说明。

- **d₁：撤回授权的操作步骤。** 设文档词权重为“撤回 1.5、授权 0.5”，则 `L_raw = 2 × 1.5 + 1 × 0.5 = 3.5`；相关。
- **d₂：取消先前权限的完整说明。** 在手设的词项单位下没有共有项，故 `L_raw = 0`；相关。
- **d₃：新增授权的收费说明。** 只有“授权”共有，文档权重为 1，故 `L_raw = 1`；不相关。

将这些词项分数与手设的 dense 分数放在一起。窄屏可横向查看整表。

| 文档 | L_raw | D（设定） |
| --- | --- | --- |
| d₁ | 3.5 | 0.45 |
| d₂ | 0 | 0.90 |
| d₃ | 1 | 0.80 |

在这个定义下，没有共有词项就没有交集贡献，单纯把已有词项权重学得更好不能给空交集增加匹配。dense 打分允许另一种相近关系；表里的 d₂ 得到了高分，但无关的 d₃ 也很高。后一现象来自我们设置的数字，不是对真实 BGE-M3 的观测。

### 混合两种分数，究竟增加了什么能力

BGE-M3 官方文档还给出多种分数的加权组合。为了单独检查这项操作，我们先只组合两路，并人为以 3.5 除掉本小集合的词项分数，令 `L = L_raw / 3.5`；这只是本例的缩放，不声称是该模型的默认归一化。

```text
H_alpha(d) = alpha × L(d) + (1 - alpha) × D(d)
0 ≤ alpha ≤ 1
```

取 `alpha = 0.5`，三个分数依次为 `0.7250`、`0.4500`、`0.5429`，因此前两名仍是 d₁、d₃。能不能再调一下权重，让两篇相关文档 d₁、d₂ 同时排在 d₃ 前面？把它们各自需要的条件解出来：

```text
d₁ 超过 d₃：alpha > 49/149 ≈ 0.3289
d₂ 超过 d₃：alpha < 7/27  ≈ 0.2593
```

两个区间没有交集。因此，**固定这组分数时，没有一个上述非负凸组合权重能把两篇相关文档同时排进前二**。这比试几个权重后说“效果不好”更具体：我们已经知道，只继续调整这一个参数解决不了设定中的排序要求。

这个反例不否定 hybrid。保持其他设定不变，只把无关文档 d₃ 的 `D` 改成 `0.20`，在 `alpha = 0.5` 时它的混合分数就降为约 `0.2429`，两篇相关文档都能排在它前面。组合能否帮助，依赖各路已经表达出的区别和组合形式。原设定还可以考虑不同的非线性排序或更有辨别力的表示；演算没有证明哪种真实模型能做到，也没有证明必须增加新字段。

还要问打分发生在哪里。若先只按本例的词项分数保留前二，候选就成为 d₁、d₃。之后只重排这两项的 reranker 无法返回从未进来的 d₂。引入另一条候选路径、扩大或重新组织候选集合，才会改变这个可选范围；它同时改变了预算与访问条件，不能算作在原集合上单纯重排。这与[记录、索引和系统角色](records-representations-systems.md)的区分相接：同一个最终名次背后，可能是不同环节给出了限制。

这些推导留下一个积极的诊断办法：先固定任务需要区分什么，再逐层检查单位、得分、组合和候选范围；选择能够改变当前限制的动作。把所有失败归给“语义不够好”，或把所有改进交给调权，都还没有定位到机制。

## 两个 recall，两个参照集合

设文档只有 a 到 h。针对当前需求，原创设定的相关集合为 **R = {a, d, e, f}**。给定向量及距离下，精确最近邻前三名为 **N₃ = {a, b, c}**。一个近似方法恰好返回 **A₃ = {a, b, c}**。

近邻集合召回在本例定义为 `|A₃ ∩ N₃| / 3`，因此是 `3/3 = 100%`。而针对信息需求：

- `Precision@3 = |A₃ ∩ R| / 3 = 1/3 ≈ 33.3%`
- `Recall@3 = |A₃ ∩ R| / |R| = 1/4 = 25%`

索引完全恢复了设定中的精确邻居，却只取到一份相关文档。近似误差在这里为零，相关性差距仍然存在。这个演算只依据设定的集合，没有运行 embedding 或 ANN 软件，也没有把八个字母冒充真实语料。

[Faiss 的搜索定义](https://faiss.ai/)以给定向量和度量为对象；[IR 的 precision 与 recall](https://nlp.stanford.edu/IR-book/html/htmledition/evaluation-of-unranked-retrieval-sets-1.html)以相关判断与返回集合为对象。混用参照集合，会让同一个“召回率”回答不同问题。

## 精确率和召回率一定此消彼长吗

仍固定 R，把返回前三名改为 **B₃ = {a, d, e}**。此时 precision 是 `3/3 = 100%`，recall 是 `3/4 = 75%`。两者同时上升。固定返回数量和相关集合时，多找到一个相关对象，两个比例都会改善。

另一种情况是沿同一排序放宽返回数量。加入一份不相关文档会降低 precision 而不提高 recall；加入一份相关文档会提高 recall，precision 如何变化还取决于原来的比例。所谓取舍，需要说明改变的是阈值、预算、排序还是表示。

这个区别也防止我们把 lexical 与 semantic 的选择直接等同于 precision 与 recall 的取舍。前一组描述匹配机制，后一组描述评价结果；实际关系需要任务与数据来建立。

## 已经获得的理解与继续位置

现在可以把三个问题分开：有没有找到给定度量下的邻居，邻居是否与需求相关，返回的信息是否在后续任务里发挥作用。每一问都可以继续深入。

现在还可以继续问：多向量的细粒度匹配改变了哪一种可表达的比较？训练出的词项权重与手工词频公式分别在学习什么？[索引也能学习](what-an-index-learns.md)提供了从输入—输出目标继续拆解“学习”的另一条线。

下一次可以从训练正负例入手：一项模型把什么当作相关，与使用者此刻需要什么，有哪些一致与差异？也可以先改变本例的需求，使相关集合变成另一组，观察同一排序为什么获得不同评价。正文中的演算已经足以独立阅读，网页演算只是方便比较的另一种呈现。
