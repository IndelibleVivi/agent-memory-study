# LongMemEval-V2 alias/order pre-registration and feasibility audit

This public artifact freezes and executes the model-free gates for a proposed
`Alias x observable-order x prose-admission` successor study of current-source
AgentRunbook-C. It asks whether a reproducible paired panel exists in the public
files, whether the proposed identity and order interventions are mechanically
distinct, and whether the exact controller candidate passes the preregistered
no-bypass local signing-trust gate.

It does **not** run a controller, reader, judge, tokenizer, or benchmark scorer.
It reports no answer accuracy, controller-frequency estimate, reader effect,
Table 2 attribution, or claim about the May 2026 run.

## Result

The locked public question and haystack maps contain 422 eligible text-only
questions after excluding 29 image-bearing gotcha items. The revised selector
chooses every exact ordered-Medium class containing at least one answerable and
one abstention question of the same domain and base type. It yields exactly
three classes and six questions; all are `web x procedure`.

The official renderer erases a pure reversal of synthetic filesystem
materialization order: concise and full summaries remain byte-identical. Its order is instead
`start_url`, `goal`, then `trajectory_id`. A rank-preserving opaque alias map
changes identity tokens without changing the ID tie-order, while a non-rank-
preserving map can change that order.

A second checked probe pre-seeds reordered and renumbered concise/full summaries,
calls the exact current `_ensure_trajectory_summary` method, observes
`summary_rendered == false`, and verifies byte preservation through the exact
sandbox-linked `trajectories/` surface. The declared direct order treatment is
therefore complete summary-record order. Insertion/index/manifest order is a
synchronized consistency surface, not a claimed directly exposed treatment.

The proposed 66-job controller phase remains `HOLD`. Full selected-trajectory
resolution was not run, and the exact Codex CLI candidate could not produce a
version receipt: macOS Gatekeeper rejected its signing trust path with
`CSSMERR_TP_CERT_REVOKED`. No bypass was attempted and current CLI versions were
not substituted. This is an author-recorded bounded local preflight observation;
the artifact does not independently replay the binary assessment and does not
make a malware or cross-release security claim.

## Verify the checked artifact without a model

```bash
python3 research/longmemeval-v2-alias-order-preregistration/audit.py --verify-checked
```

This verifies exact checksum file-set completeness, every checked artifact hash,
and the checked decision.

To rebuild selection and renderer evidence from the official current source and
already acquired public files, use a new output directory:

```bash
python3 research/longmemeval-v2-alias-order-preregistration/audit.py \
  --source-repo /path/to/LongMemEval-V2 \
  --questions /path/to/questions.jsonl \
  --small /path/to/lme_v2_small.json \
  --medium /path/to/lme_v2_medium.json \
  --output-dir /tmp/lme-v2-alias-order-rebuild
```

The rebuild writes its own `raw/`, `RESULTS.txt`, and exact-file-set checksum
manifest entirely beneath the requested output root; it never rewrites this
checked publication directory. Compare every generated byte with the checked
artifact using:

```bash
python3 research/longmemeval-v2-alias-order-preregistration/audit.py \
  --compare-checked \
  --output-dir /tmp/lme-v2-alias-order-rebuild
```

No third-party Python packages are required. Rebuild requires Python, Git, the
three locked public data files, and a clean checkout of the locked source commit;
it makes no network or model call. It verifies exact public-data/source hashes,
the complete eligibility pool, all Medium equivalence classes, selected Small
equality, the renderer controls, and the exact pre-seeded summary bypass surface.

## Boundary

This is a census of what can be selected from the locked public metadata and a
feasibility audit of the planned intervention. It does not reconstruct hidden
official source-pair provenance. Absence of an exact public class does not prove
that no hidden pair exists. The three selected classes do not support claims
about enterprise, static, dynamic, gotcha, multimodal, or all-451-question
behavior.
