# 任务改变以后，旧表示还足够吗？

Agent Memory Study editors · 2026-10-22 · **已执行的有限构造与精确枚举**。

本 artifact 为[记忆需要为尚未出现的问题保留什么？](../../study/entries/future-questions-and-memory.md)提供可复跑的有限见证。它检查一组历史在某种可见表示下能否共同接受同一个答案。没有调用模型、训练、embedding、检索服务、真实源档案、参与者或 LLM judge；**32 个历史是枚举出的可能世界，独立经验样本数为 0**。

## 运行

仅需 Python 3.11+ 标准库：

```bash
python3 -B research/task-relative-sufficiency/study.py
python3 -B research/task-relative-sufficiency/study.py --check
python3 -B -m unittest discover -s research/task-relative-sufficiency -p 'test_*.py'
```

默认命令重算并写入本目录的 `results.json`；`--check` 重算后与保存结果比较。要保留另一份输出，使用 `--output /fresh/path/result.json`，该路径已存在时拒绝覆盖。无时间戳、随机采样、网络调用或运行环境依赖的输出字段。fixture 的 canonical JSON SHA-256 只绑定研究输入身份，不参与任何可见表示。

## 精确对象

对历史 `h`，投影 `T` 产生可见表示 `T(h)`。问题 `q` 的可接受答案集为 `A(h,q)`；这组人工定义的合同与观察分开。相同可见表示的全部历史组成观察类：

```text
C_T(z) = { h ∈ H : T(h) = z }
compatible(z,q) ⇔ ⋂ { A(h,q) : h ∈ C_T(z) } ≠ ∅
```

交集为空时，无论解码器怎样选择一个答案，它都会在该类至少一个历史上违反合同。交集非空只说明在这个**有限候选历史集合**里允许一个共同答案；没有证明自然语言理解、计算可行的解码器、模型效果或集合外泛化。知识背景、task wording 和可用通道在 `fixtures.json` 的 `declared_side_information` 中声明。未来有更多可能历史时，原有非空交集可能变空。

评价使用完整观察类的交集。三个集合 `{direct,cached}`、`{cached,replay}`、`{direct,replay}` 两两相交，整体交集为空；runner 会实际找到三历史最小冲突见证，不能用“两两没有冲突”替代全类检查。任务要求选择一条路线，不能把全部候选当作答案。当前合同也不把暂缓作为普遍正确答案；研究恰当暂缓需要另设真实的允许条件。

## 原创历史与投影

两个事件分别记载 v1 和 v2 的格式；v1 的说话人、明确理由和逐字措辞也可变化。四个事实二值轴与一个措辞二值轴相乘，形成 32 个历史。所有名字、事件和文本由本 artifact 原创，与私人生活、项目日志和上游 benchmark 无关。

| 投影 | 输入中保留什么 | 本次观察类数 |
| --- | --- | ---: |
| `current-summary` | 当前 v2 与格式 | 2 |
| `version-relations` | v1、v2 各自绑定的格式 | 4 |
| `scoped-relations` | 两个版本的格式、说话人、明确理由 | 16 |
| `expanded-summary` | 仅从 current-summary 生成较长说明 | 2 |
| `raw-events` | 原始合成事件的完整结构与措辞 | 32 |

投影函数只接收事件，不接收问题、答案集、`audit_id` 或 evaluation 输出。材料、投影与问题由本轮共同设计，属于开发构造；执行时的 query-independent 不意味着设计者没有看过未来任务，也不构成 held-out 泛化实验。`scoped-relations` 将两个措辞不同的历史放在同一类，是有意保留的压缩正对照。它能满足这里四项语义字段任务的有限兼容性检查，同时无法满足新增的逐字措辞任务。该“压缩”指多个原历史映射到同一表示，不指 token 或字节压缩率。

## 实际结果

所有任务族使用同一份历史；增加问题时没有加入新事件。

| 表示 | 当前格式 | 加入历史格式、说话人、明确理由 | 再加入逐字措辞 |
| --- | --- | --- | --- |
| current-summary | 全部观察类兼容 | 出现空交集 | 出现空交集 |
| version-relations | 全部观察类兼容 | 出现空交集 | 出现空交集 |
| scoped-relations | 全部观察类兼容 | 全部观察类兼容 | 出现空交集 |
| expanded-summary | 全部观察类兼容 | 出现空交集 | 出现空交集 |
| raw-events | 全部观察类兼容 | 全部观察类兼容 | 全部观察类兼容 |

`results.json` 保存每一个实际可见 observation、仅供审计的成员标识、每个任务的完整交集与最小空交集见证。没有隐藏只对主张有利的类，也没有把这些组合汇总成模型准确率。

## 源文重访的单独控制

第二组构造把 current-summary 与合成原记录的重新提供放在一起。只有 `permitted`、`available`、`correct_revision`、`target_bound`、`adequate_coverage` 五项均为真，resolver 才提供完整原记录。每次分别关闭一个条件，源内容都保持不可见，后来任务仍有空交集；全开条件下，完整记录使有限任务族全部兼容。

这里没有访问真实源文件。这是预先声明的、保守的全部通过才返回原文的 resolver，不模拟真实部分检索；`adequate_coverage=false` 不等于现实系统任何内容都不可用。它检验的是**不能把未真正到场的源内容计入观察**。各条件状态在同一处理下对全部历史相同，不编码隐藏答案。本模型的审计标识与哈希不进入观察；未声明可解码语义或映射的 locator 不自动算作原文。其他系统若给标识赋予内容或查表映射，应将它明确写入侧信息，重新计算观察类。

原文仍存于档案、当前表示已丢失区别、源文未进入候选、候选未送达、已送达后未被使用，是不同事件。本 artifact 只枚举给定可见信息的兼容性，不从答案倒推发生在哪个实际环节。

## 验证与解释边界

九项行为检查覆盖：任务族扩大、压缩正对照、三集合全局冲突、确定性扩写不恢复区别、五项源条件、审计身份隔离、枚举次序不变、修改原记录后重算合同，以及非空单历史答案／非普遍暂缓条件。它们验证这个 runner 的研究合同。

文章中的一般命题有独立推导；有限枚举没有证明普遍规律。本文也不提出“始终保留一切”的存储规则：权利、访问限制、存储预算、任务概率、模型先验和人的感受都未进入本模型。源文增加了可用观察之后，检索代价和实际消费质量仍需单独研究。
