# Reader 侧信息干预协议

**执行版方法，2026-11-07；在正式测量前冻结。** 运行状态及观察结果由 [README](README.md) 和 `reader-results.json` 单独记录。本协议不自动触发 API，也不授予后续研究权限。原 `study.py` / `results.json` 和选择渠道的 `selection.py` / `selection-results.json` 保持各自有限计算的身份。

## 1. 这次能够回答什么

问题是：固定的两类记忆，在同一自然语言 reader 已获得不同侧信息时，是否出现用途次序反转？另区分它是否正确绑定项目，或只是看到任何编码册便套用。

H1：同项目解释键使编码记录可用，而独立的其他项目键没有这种帮助。H2：格式、额外文字或位置带来的变化足以解释主效应。H3：reader 连信息充分的完整映射也无法使用。H4：reader 错用无关键；主准确率可能掩盖这种错误。

这是一个有明确生成分布的短文本解释任务。它不测长期记忆保持、检索质量、真实任务分布或架构收益。即使全部通过，也只建立这个窄场景中的可行性与正确项目绑定，不成为建设复杂 selector 的理由。侧信息就在当前上下文，不被称作模型持久记忆。

## 2. 完整刺激与实际调用单位

Θ、C 独立均匀；E 独立且 P(E=1)=1/4。X=Θ XOR C，Y=Θ XOR E；沿用 `study.py::channels(True)` 的八个世界，E=0 行权重 3/16，E=1 行权重 1/16。项目 Q 的键 D 在每个世界内独立枚举 0/1，各半权重。A 对应 Θ=0，B 对应 Θ=1。

全部请求使用 `reader.py::SYSTEM` 的同一说明：A/B 先验各半；各项目独立、等可能选择两种双射编码册；编码记录无误，抄录单独立地有四分之一概率写反；记录类型由外生固定安排提供；强制二选一并报告 p_A。明确编码册的公平先验，是确定缺键时规范后验所必需的假设。

| 成分 | 渲染规则 |
| --- | --- |
| X=0/1 | 项目 P 的样本代号：青石／云母 |
| Y=0/1 | 项目 P 的抄录单目的地：A／B 柜 |
| 有效键 | 项目 P 编码册，青石映射至 C 对应的柜，云母映射至另一个柜 |
| 无关键 | 完全同格式的项目 Q 编码册，映射由独立 D 决定 |
| 无键辅助 | 仅给 X 或 Y 记录，没有编码册；长度不匹配，不能替代主对照 |

当前问题始终为“项目 P 的这份样本应送到 A 柜还是 B 柜？”。实际消息由 `reader.py::render` 唯一生成；它仅接收可见记录、项目与映射，不接收整个 latent world、gold、E 或未暴露记录。

主设计为 X/Y × 有效/无关键。编码册两行顺序、编码册在记录之前/之后独立平衡。完整 A/B 名称和代号置换后的刺激仍在这个封闭输入集合内：逐字相同的消息去重，不添加调用或宣称跨词汇泛化。主设计共 64 条不同 messages；无键辅助另有 4 条。它们覆盖 272 条带权评价行；这些行不是独立任务。

每条不同 messages 预定独立调用 3 次，共 **204 次正式调用**。同一次调用的回答复用于所有与该输入兼容的 latent 世界；不能为不可见噪声重复调用并虚增样本。三次重复只描述调用稳定性，不当作新任务家族。用固定 `order_seed=20261107` 打乱全部调用，四个并发；这是本地调度 seed，不是 provider sampling seed。

## 3. 模型、输入冻结与预算

固定官方 OpenAI Responses API 的 `gpt-6.1-sol`、`reasoning.effort=low`、standard `service_tier=default`、`max_output_tokens=2048`，`store=false`。不发 temperature、top_p 或 sampling seed，记录 provider 返回配置；不声称确定性。该模型当日目录只列同名 snapshot/alias，没有可进一步锁定的日期版本，保存实际返回 model 字符串及运行时间。每次全新上下文，无 conversation、previous_response_id、工具或检索。Structured Outputs 只限制 `{choice, p_A}` 的结构，不提供答案。

`prepare` 在 repo 外分别冻结 `reader-inputs.json`、`evaluator-truth.json`、manifest 与 source identity。API 层只发送 messages 和固定配置，request ID、source path、world、gold、cell、权重与预期 cell 分数都不进入模型。实际发送的 JSON 字节在调用前落盘；原始 response、错误、usage 与逐请求身份一并保留。完整文件排他发布，不覆盖旧 run；中断后的请求没有 response 时，可能已送达，不能自动重发。

一次不含研究映射的格式 canary 单独保留、不计入结果；然后用官方 `/responses/input_tokens` 对全部 68 条输入计数，包含 message/schema 开销，验证有效/无关键的 32 个相同记录、映射、顺序配对 token 数相同。若不相同，先停止并修正刺激；不得看过正式结果后悄悄补齐。

预算上限 **5 USD**，包括 canary 和正式 generation。预检按每次最大 2048 output tokens、实际 input tokens 及较高的 cache-write input 单价保守预留；价格依据是当日官方模型页（普通输入 2 USD/M、cache write 2.5 USD/M、输出 10 USD/M）。token count 是非 generation 请求，数量另记；未把 token count 响应当模型行为。结果中的 usage 估价不是账单或当前 credits 余额。

不自动重试任何测量。拒绝、无效 JSON、非法概率、HTTP 错误与超时均留在记录中。累计三个 HTTP/transport/incomplete 错误后，在当前最多四请求的批次结束时停止，不再提交新批次；可能超过三项但不会超出计划总数。格式无效不触发挑样重跑。预定 204 次完成即止，不依据 D 或第三次是否“好看”追加样本、换模型、调 prompt。服务失败、预算或输入身份异常会使本轮成为未完成运行，不能包装成完整实验。

## 4. 主要结果与能揭穿错误解释的诊断

主要结果是按世界分布权重的强制选择正确率，四个原始 cell 与交互量均报告：

```text
D = [Acc(X, 有效键) − Acc(Y, 有效键)]
  − [Acc(X, 无关键) − Acc(Y, 无关键)]
```

无效或缺失 choice 在计划分母内计零，并单列缺失质量。校准仅对合法 p_A 计算，明确其覆盖比例，不把缺失 p_A 补成 .5。每次重复、四个 order 组合单列；不对八个有限世界或其重复计算“泛化显著性”或任务抽样置信区间。

**D=.5 不是足够的机制证据。** X+无关键的信息不足；任何合法二选一策略的期望准确率都是 .5，甚至盲用 Q 编码册也如此。因此预定同时报告：

- Brier score 及相对真实可见输入后验的平均绝对偏差。规范 p_A 由 evaluator 对同输入的世界边际化计算；理想值是解释参照，不是 LLM 评分合格线。p_A 是报告行为，不等于模型内部信念。
- 翻转编码册映射前后 p_A 的平均绝对变化、沿映射所指答案方向的有符号变化，以及 choice 翻转率。X+有效键固定 X 翻 C 时，配对世界的 Θ 同时翻转；不能声称固定真实答案的干预。X+无关键翻 D 保持世界真相不变。Y 组也检查无关映射敏感性。
- 同输入三次调用的概率 range。无信息时 choice 在 A/B 间变化可以只是合法 tie-breaking，不能仅凭 choice flip 宣布错用记忆；必须结合概率和映射方向。
- 无键辅助的 X/Y 分数和概率偏差，用于区分其他项目编码册造成的干扰与 reader 缺键时本来的过度确定。它不与等长主对照混合成主要 D。
- choice 与 p_A 的决策一致性；p_A>.5 却选 B、或 p_A<.5 却选 A 单列，不自动修正输出。

X+有效键已含完整且无噪声的解释信息，兼任解码能力 positive control，不重复添加同义任务。无记录、只给侧信息的实际 reader baseline 本轮不测；因此记忆“增量”只能相对理论无记录 .5 基线解释，实际测得的是固定 X/Y 用途次序与 side-information effect。

## 5. 结论边界与后续分岔

若有效键对 X 有明确选择性帮助、Y 稳定、顺序变体一致，而且无关键不会引发沿错误映射的概率变化，才支持此读者在此任务中使用了有项目边界的互补信息。若 D 符合理论而无关键概率跟随 Q，报告“正确率掩盖了错误绑定”，不能只展示成功的主表。若有效键条件失败，报告能力限制；若概率正确但强制选择有偏，区分决策行为与信息判断。

即使是 clean positive，也不证明真实 memory selection 有收益。下一阶段应研究同一实际 reader 下哪些可见状态变化破坏用途标签迁移；selector 仍需另行规定渠道，不能自动继承固定暴露的 D。原始材料和运行保存在 repo 外；公开结果只含原创刺激生成器、方法与汇总，不发布账号标识或私有执行 traces。离线验证可重算 scoring 和检查 compact summary，不能冒称重新调用 provider 或拥有公开 raw replay。

## 6. 未来加入 selector 时，不能省略的信息边界

这一节规定后续设计需要区分的对象，不把当前语言实验改成 selector 实验。[正文第七节](../../study/entries/memory-value-side-information.md)与 `selection-results.json` 已用有限世界展示三种机制：相同正文的身份传信、身份与正文互补，以及隐藏身份后仍由所选正文传信。

- 分开记录候选池 U、selector 实际可见的信息 Z、reader 已有信息 C_R、选择策略版本、所选身份 J 与顺序、实际交付正文 P。Gold 只归 evaluator；允许 selector 看到的推断依据不等于允许看到答案。
- 固定暴露的记录价值与自适应选择后的整体价值分报。一个知道 π 的理想读者与一个实际语言模型不是同一条件；若模型从示例、训练或指令获得选择规则，要记录这项输入。
- 在相同正文的控制中比较显示/隐藏身份，检查身份作用；再检查身份与正文的联合条件。身份单独不能预测目标不能排除互补传信，隐藏身份也不能排除正文选择的作用。
- 随机选择须独立于当前世界，明确保持了哪些边际、条数或成本。一般候选池中的随机选择会同时改变正文，不自动隔离“身份贡献”；不能把几个 accuracy 差相加当成因果分解。
- 全候选基线须列出是否还获得 selector 额外可见的 Z。只给 U 的基线不能被称为完整信息 oracle；给 U、Z、C_R 的理想值也不保证有限模型处理长输入时达到同样结果。
- ID 改名若用于数学等价性检查，应同步更新所有映射；若仅改名而不更新模型学到的含义，测试的是编码的迁移脆弱性。两种干预分开报告。返回顺序、来源标签与推荐理由亦属于实际消息，不能只数正文 token 后宣称传递成本相同。

只有已声明部署时可得的输入参与选择，整体效用才有相应的部署解释。若目标是评价正文证据的充分性，还需另设固定暴露或独立选择条件；对系统有益的选择推理并不自动构成忠实的正文解释。
