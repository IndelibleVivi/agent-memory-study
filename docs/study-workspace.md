# 把几份材料放到同一张案头

研究案头用于整理一次跨材料的思考。可以只有一个陌生词，也可以并读文章、来源札记、问题专题与实践判断。它不要求先建立正式 inquiry，不给研究进度或个人理解打分。

## 一次完整使用

1. 阅读正文时，点击标题下的“加入研究案头”，再点“回到研究案头”。也可以从主导航进入案头，用“选择公开内容”查找对象；这里的搜索只在内存中，不写 URL。
2. 例如，选择《找到一样的，还是找到相关的？》和《索引也能学习——究竟学了什么？》，比较检索的评价对象与学习映射的输入、输出。把问题、已经讲清的解释与下一步写在案头里。
3. 案头保留所选对象的顺序；上移、下移、移出均有明确对象。“放入对读”最多同时放入两个对象。文章正文由同一 compiler 生成；来源、专题和实践判断先并列核心内容与范围，完整论证、实验与证据可从“打开完整正文”或研究包继续读。
4. 每个对读对象下可以写自己的笔记。在当前公开正文中选中文字，点击“留下选中文字”，再在案头为摘录标记背景、支持、对照或疑问，并写批注。详情正文有选区时，操作会出现在当前视口，不必返回长文开头；清除选区或完成摘录后收起。摘录保留当时的来源快照、内容日期和可获得的章节位置；这些用途是你的判断，不自动成为公开支持关系。每对象最多 12 条摘录，每条文字和批注各限 8,000 字符。
5. 详情标题下的“沿引用继续读”分开列出本对象的出处与引用者，可打开正文或加入案头；间接检查范围沿反向引用列出修订时值得重读的条目。它只使用显式引用，不判断论证依赖、支持强度或相似度。
6. 打开正文、回到案头和站内 back / forward 都保留页面内的工作；单篇详情底部的接续笔记与案头共享同一条文字。
7. 点击“保存案头 JSON”下载可重新打开的文件。回来后选择“打开案头文件”，先核对文件名义下的对象列表，再点“打开这份案头”；在确认前当前工作保持原样。打开会替换当前案头，可用“撤销上次整理”恢复打开前的状态。新文件使用 `ams-workspace/2`；已有 `ams-workspace/1` 文件仍可打开，缺少摘录的旧记录按空列表迁移，原笔记和依据保留。

案头最多保留 24 个对象；文件上限为 2 MiB。笔记只在本页内存和主动下载的文件中，刷新、关闭或离开页面会丢失未保存内容；有修改时浏览器会请求离开确认。浏览器是否展示确认受其用户交互规则约束，不能把提示当成备份。下载文件仍由你保管，没有账号、在线批注或云同步。

“撤销上次整理”和“重做整理”贯通文字编辑、摘录、选材、排序、对读、依据确认和文件打开。一段连续聚焦的文字编辑合为一步；可以逐步返回，也可以重做，撤销后开始新编辑会结束原重做分支。页面最多保留最近 20 次变更，历史总量限 8 MiB，较大的案头可能保留更少步骤。它不是永久版本库，也不替代编辑框内浏览器原生的逐字撤销。保存后的撤销仍然可用；是否有未保存改动按整个案头与最近保存／打开的检查点比较。页面同时显示文件大小；超过保存上限的操作整体拒绝，已有案头保留。

自动记录章节或演算状态也遵守容量上限。如果补记位置会超限，文章和案头显示“未更新本次继续位置”，已接受的笔记、快照和历史保持原样，站内导航仍可使用。此时保存案头会下载最后接受的状态；单篇接续仍可保存当前文章的笔记、位置与演算选项，但不会把未保存的案头改动标成已经保存。先保存已有案头，再分开整理，便可为后续变化留出空间。

## 保存私人工作，或带走公开选材

| 出口 | 包含什么 | 能否重新打开为案头 |
| --- | --- | --- |
| 保存案头 JSON | 私人名称、问题、理解、继续位置、各对象笔记、摘录／批注／用途、位置和各自来源快照 | 可以；不包含页面撤销历史 |
| 私人札记 Markdown | 私人文字、摘录与批注、顺序、来源位置、内容日期、版本状态与当前公开研究包 | 作为文字阅读；不是案头恢复格式 |
| 公开选材 Markdown / JSON | 当前所选公开对象的正文或札记、署名、范围、显式引用 manifest | 作为公开研究包阅读；不含私人案头 |
| 单篇接续 JSON | 既有 `ams-continuation/1` 的一个对象、笔记、位置和支持的演算状态 | 用首页“打开接续文件”恢复 |

公开选材导出不包含私人案头名称、问题、理解、继续位置、笔记、摘录记录／用途／批注或保存的旧快照。公开正文自身可能含有同一段文字，这不意味着私人记录被导出。它不递归抓取来源全文，也不会把几篇材料并排就称为相互支持。私人 Markdown 可以包含你的任何文字；准备分享或发表时，应自行核对其内容、署名与权利。

索引文章支持保存分布、是否插入、索引维护方式和查找键；单篇接续与案头使用同一状态归一化。恢复时重新计算当前教学程序，不把文件中的旧结果当作可信答案。旧检索集合演算的 `k`、排序与相关集合继续兼容。演算 URL 可分享固定公开选项，私人笔记不会进入其中。

## 正文变了以后

案头 JSON 保存所据公开内容的惰性快照。再次打开时，对读展示当前公开正文，笔记保留原样；即使编辑日期相同，内容变化仍可被发现。“查看保存内容与当前内容”列出变化字段，可并列阅读旧／新文字。它不是语义 diff：metadata、HTML 编译结果或正文格式的变化不一定改变论点。

确认重读后，可以点“已核对，改以当前正文为据”；这只改变对象笔记的比较基准。**已留下的摘录仍保留各自的旧快照**，不会因为对象确认而被改写成“来自新版本”。摘录中的“回到来源”打开当前公开正文，旧文字只在摘录和快照比较中保留。选区必须来自当前公开内容，不能跨入私人输入框；导入摘录本身不因此获得真实性认证。

旧单篇接续只有日期，无法据此确认正文是否相同；界面明确保留这个限制。缺少快照、身份／格式不匹配与有效快照的内容变化分别显示。快照比较不认证来源或文件持有人；无法比较的原文字仍保留。导入文件中的文字和 HTML 只按纯文字显示，不执行、不替代当前正文、不请求文件中的 URL。未知对象、无效字段值、重复对象／摘录身份、过大或损坏文件会被拒绝，现有案头保持原样。

## 给机器带走一组选材

公开包与网页使用同一个 `StudyPackets` projection：

```bash
node tools/export_study.cjs \
  --select study:retrieval-and-relevance \
  --select study:what-an-index-learns \
  --format markdown

node tools/export_study.cjs \
  --workspace /path/to/ams-workspace.json \
  --format json --out /path/to/public-selection.json
```

第二条命令只读取案头中已知的公开对象身份，从当前数据重新生成公开包；私人文字和旧快照不输出。三种输入方式（单篇 `--kind` / `--id`、重复 `--select`、`--workspace`）互斥，`--out` 拒绝覆盖已有文件。新选材包使用 `ams-study-collection/1`，每个对象仍是已有 `ams-study-packet/1`。

如果要让另一个 agent 接着读私人思考，可以主动向自己授权的环境提供案头文件或私人 Markdown；它们没有自动上传路径。任何包里的研究文字都属于待阅读材料，不获得执行指令身份。

## 接到一篇作者草稿

案头文件可经离线作者入口整理成 repo 外的 draft Markdown 与 metadata。它保留私人文字、摘录、来源范围和版本限制，不替你完成论证，不自动登记 `readings` 或写回研究体。具体命令和正式采用前的核对见[作者指南](authoring.md)。
